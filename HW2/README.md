# ПОС — Преподавательская Оценка Студентов

Учебное консольное приложение на C# / .NET 10 по заданию «КПО, ДЗ №2». Поддерживает студентов, рубрикатор, выставление, исправление и отмену оценок, взвешенные итоги, средний балл и экспорт CSV. Данные сохраняются в JSON между запусками.

## Запуск

Нужен **.NET SDK 10.0.400 или более новый SDK 10.0**. Открыть `Pos.sln` в Rider либо выполнить из корня:

```bash
dotnet restore Pos.sln
dotnet build Pos.sln --no-restore
dotnet run --project src/Pos.Console
```

В меню используются номера строк, вводить GUID не требуется. Числа принимаются с точкой или запятой, без разделителей тысяч. Изменения сразу сохраняются. Пустая строка в комментарии допустима. `0` или конец входного потока завершают приложение. Удаление студента/критерия требует ответа `да` и удаляет связанные оценки.

```bash
# Изолированная демонстрация, не изменяет основную JSON-базу:
dotnet run --project src/Pos.Console -- --demo

# Своя база и альтернативное правило для пропусков:
dotnet run --project src/Pos.Console -- --data data/my-course.json --policy evaluated

# Справка:
dotnet run --project src/Pos.Console -- --help

# Тесты и покрытие:
dotnet test Pos.sln
dotnet test Pos.sln --collect:"XPlat Code Coverage"
```

Все относительные пути отсчитываются от текущего рабочего каталога. Обычная база: `data/course.json`; CSV демонстрации: `exports/demo.csv`. Для демонстрации можно указать `--export exports/other.csv`. Флаг `--export` задаёт путь только для демо; в интерактивном режиме путь запрашивается командой 13. CSV имеет UTF-8 BOM, разделитель `;` и десятичную точку; при импорте в табличный редактор следует выбрать эти параметры.

## Сквозной сценарий

`--demo` выполняет последовательность:

1. Создаёт Анну (S001), Ивана (S002), критерии «Проект» (максимум 10, вес 0,6) и «Защита» (максимум 5, вес 0,4).
2. Выставляет Анне 9 и 4, Ивану 7 за проект; выводит списки и оценки.
3. Пытается поставить 12 из 10: домен отклоняет операцию, оценка 9 сохраняется.
4. Исправляет проект Ивана на 8; выставляет и отменяет оценку за защиту.
5. Рассчитывает итоги: Анна **8,60**, Иван **4,80** при правиле `zero`; Иван **8,00** при `evaluated`. Итог Ивана помечен как предварительный.
6. Экспортирует отчёт в CSV. Повторный запуск демо воспроизводим, так как использует отдельное хранилище в памяти.

В интерактивном режиме доступны полный CRUD студентов и критериев, просмотр всех оценок с датой и комментарием, установка/исправление/отмена оценки, итоговый отчёт и CSV. Приложение показывает средний итог студентов; при неполных оценках средний также включает предварительные результаты.

## Правила расчёта

Используется `decimal`. Для критерия `i`: максимум `mᵢ > 0`, вес `0 < wᵢ ≤ 1`, оценка `0 ≤ sᵢ ≤ mᵢ`. Сумма весов не превышает 1. Частично собранный рубрикатор допустим: сумма не обязана равняться 1, расчёт нормируется по фактической сумме. Это позволяет добавлять критерии по одному.

```
итог = round(10 × Σ((sᵢ / mᵢ) × wᵢ) / знаменатель, 2)
```

- `zero` (по умолчанию): знаменатель — сумма весов всех критериев, отсутствующие оценки дают нулевой вклад.
- `evaluated`: знаменатель — сумма весов только оценённых критериев. Подходит для промежуточного прогресса; пропуски всё равно видны в отчёте.

Если оценок нет, обе стратегии возвращают 0 и незавершённый статус. Если критериев нет, расчёт отклоняется понятной доменной ошибкой. Если нет студентов, отчёт пуст. Округление до двух знаков выполняется один раз в конце, половины — от нуля. Явная нулевая оценка считается выставленной, отсутствие оценки — нет. Итог не хранится, поэтому исправление оценки, изменение веса или удаление критерия сразу учитывается.

## DDD: карта модели

| Термин | Реализация | Ответственность |
|---|---|---|
| Курс | `Course`, корень агрегата | Единая граница согласованности студентов, рубрикатора и оценок одного курса |
| Студент | `Student`, Entity с `Id` | ФИО, уникальный в курсе номер; при переименовании идентичность сохраняется |
| Критерий | `Criterion`, Entity с `Id` | Непустое название, положительный максимум и вес |
| Рубрикатор | `Rubric` | Неизменяемый список критериев; поиск только существующего критерия |
| Оценка | `Evaluation`, Entity с составной идентичностью `(StudentId, CriterionId)` | Балл, комментарий и время последнего изменения |
| Балл | `Score`, Value Object | Значение, неотрицательность, равенство по значению: `new Score(8) == new Score(8)` |
| Итог | `FinalScore`, неизменяемый результат | Значение, полнота оценивания, выбранная политика |
| Расчёт итога | `FinalScoreService`, Domain Service | Правило зависит от нескольких объектов: студента, рубрикатора, оценок |
| Хранилище курса | `ICourseRepository`, Repository-порт | Загрузка/сохранение всего агрегата, без знаний о файлах |

Модель не анемична: операции изменения доступны через `Course`; свойства сущностей и коллекции снаружи недоступны для изменения. `Evaluation` нельзя создать напрямую вне Domain. Перед созданием оценки агрегат разрешает ссылки на студента и критерий; конструктор оценки проверяет верхнюю границу балла. Отрицательный балл запрещён `Score`. `default(Score)` равен допустимому нулю.

`Course` обеспечивает уникальность номера студента и идентификаторов, рубрикатор — уникальность названий без учёта регистра и сумму весов. Неудачное изменение проверяется до замены состояния. Нельзя уменьшить максимум ниже выставленных баллов; нужно сначала исправить оценки. Удаление студента/критерия каскадно удаляет оценки, висячих ссылок нет.

Один агрегат курса выбран намеренно: в задании один курс, данных немного, а основные инварианты пересекают студентов и рубрикатор. Это позволяет соблюдать их без транзакций между несколькими репозиториями. Для нескольких больших курсов границы хранения и конкуренцию следует пересмотреть.

## Архитектура: Ports and Adapters

```text
Pos.Console ───────→ Pos.Application ───────→ Pos.Domain
     │                      ↑                    ↑
     └──────────→ Pos.Infrastructure ─────────────┘
```

- **Domain**: модель, инварианты, Domain Service, стратегия итога и repository-порт. Ноль внешних пакетов и ссылок на другие проекты.
- **Application**: `GradebookFacade`, сценарии CRUD, оценивания, отчёта и экспорта; DTO отчёта и выходной порт `IReportExporter`. Зависит только от Domain.
- **Infrastructure**: JSON-репозиторий, репозиторий в памяти для демо, CSV-адаптер, DTO хранения и восстановление модели. Зависит от Application и через него от Domain.
- **Console**: входной адаптер; меню, разбор ввода и аргументов, обработка ошибок. `Program.cs` — composition root: `Microsoft.Extensions.DependencyInjection` собирает конкретные адаптеры, `TimeProvider`, выбранную стратегию и фасад. Ссылка Console на Infrastructure нужна для этой сборки.

UI не рассчитывает итоги и не сериализует доменные объекты. Фасад загружает агрегат, выполняет операцию и сохраняет только после успеха. Репозиторий возвращает независимый снимок. При загрузке JSON сущности восстанавливаются через доменные операции: редактирование файла вручную не обходит инварианты. Версия формата проверяется, неизвестные поля, пропущенные обязательные поля и дубли оценок отклоняются.

Запись JSON и CSV выполняется через временный файл в том же каталоге и переименование. Повреждённый JSON не считается пустой базой и автоматически не перезаписывается: приложение сообщает ошибку. Для восстановления нужно исправить файл или явно выбрать другой `--data`. Предполагается один запущенный процесс на файл; межпроцессные блокировки и многопользовательская работа вне объёма этого задания.

## Три паттерна GoF

| Группа | Паттерн и место | Какую задачу решает |
|---|---|---|
| Порождающий | **Builder** — `RubricBuilder.Add().Build()` | Собирает рубрикатор с проверкой дубликатов и суммы весов, публикует независимый неизменяемый результат. Используется при создании и каждом изменении рубрикатора, включая загрузку JSON |
| Структурный | **Facade** — `GradebookFacade` | Даёт UI завершённые операции; скрывает координацию репозитория, доменной модели, расчёта и экспортера. Меню не повторяет load/change/save |
| Поведенческий | **Strategy** — `IFinalScoreStrategy`, `MissingAsZeroStrategy`, `EvaluatedOnlyStrategy` | Переключает смысл пропущенных оценок без изменений алгоритма нормирования и UI. Конкретная стратегия выбирается DI по `--policy` |

Дополнительные паттерны ради количества не добавлены. Repository — строительный блок DDD, DI — способ сборки зависимостей; они не выдаются за дополнительные GoF-паттерны.

## Проверки

`tests/Pos.Tests` содержит xUnit-тесты домена и интеграционные тесты с настоящим файловым адаптером. Проверяются границы балла, неизвестные ссылки, исправление/отмена, уникальность, Builder, изменение критерия, каскадное удаление, обе стратегии, отсутствие оценок/критериев, вычисление 8,60, сохранение и повторная загрузка, повреждённый JSON, неизменность файла при отказе, CSV-экранирование и изоляция снимков. Тесты используют отдельные временные каталоги, пользовательскую базу не трогают.

Проверено в окружении .NET SDK 10.0.400: сборка без ошибок и предупреждений, **40/40 тестов проходят**. Покрытие строк по Coverlet (Release): Domain **100%**, Application **82,8%**, Infrastructure **90,1%**. Покрытие не означает доказательство корректности всех возможных входных данных. Дополнительно проверен реальный консольный ввод: CRUD, обе формы десятичных чисел, ошибочный ввод, повторное открытие базы, отмена/каскадное удаление, CSV и обе стратегии.
